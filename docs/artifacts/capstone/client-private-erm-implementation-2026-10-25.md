# Scalar client-private ERM comparator implementation

25 October 2026. Generated-data implementation checks only; no patient fitting or scoring was performed.

`repro/client_private_erm.py` implements the scalar-logit comparator derived in `phase-3-mechanism-preparation-2026-10-25.md`. A central coordinator receives all feature rows and labels. The objective equally averages the nonempty clients' mean binary logistic losses, plus `lambda * ||theta||² / 2`. Before fitting, each feature row is clipped to the fixed public L2 bound B; an intercept is appended afterward and receives the same regularization as every weight. The output has d+1 coordinates, ordered weights then intercept.

`fit_client_private_erm(x, y, partitions, *, row_bound, regularization, steps, max_steps=100_000)` accepts numeric array-like features of shape (m,d), binary labels of shape (m,), and a list or tuple of nonempty integer row-index vectors. Partitions must be disjoint and exhaustive. It computes in CPU NumPy float64, copies inputs, starts at zero, and takes exactly T=`steps` full-gradient updates of size `1 / beta`, where `beta=lambda+(B²+1)/4`. It never uses a convergence threshold to stop, reject or retry.

The returned dictionary contains raw `theta` (NumPy float64 vector), `public_bound` (public scalar constants and sensitivity components), and `research_diagnostics` (feature clipping rate, final objective, final gradient norm and completed step count). The diagnostics are explicitly labelled `NOT_DP_OUTPUTS`. Raw theta and diagnostics must not be treated as private releases. One additional final objective/gradient evaluation supplies diagnostics and never controls optimization or release.

`bound_rows(x, row_bound)` returns a copied NumPy float64 matrix with the exact same feature-row clipping kernel used by fitting. Evaluation must apply it before computing the scalar margin `bounded_x @ theta[:-1] + theta[-1]`. It appends no intercept and never mutates the input. The fitting helper receives no evaluation data.

`solver_sensitivity_bound(*, row_bound, regularization, num_clients, steps)` returns L, beta, q, T, exact-minimizer sensitivity `2L/(lambda*n)`, finite-solver residual `2*q**T*L/lambda`, and their sum under `sensitivity`. Here `L=sqrt(B²+1)` and mathematically `q=1-lambda/beta`. It uses the equivalent ratio `(B²+1)/(4*beta)` to avoid subtraction cancellation.

`choose_solver_steps(*, row_bound, regularization, num_clients, residual_ratio, max_steps=100_000)` uses only public constants to select T so that the residual is at most `residual_ratio` times the exact-minimizer bound. It exposes the chosen T and both components in the same bound dictionary. It rejects budgets exceeding the supplied public maximum. A check of the computed bound corrects logarithmic rounding at integer boundaries. No private convergence measurement chooses the budget.

`release_gaussian(theta, *, sensitivity, noise_multiplier, seed)` returns a dictionary containing the perturbed `theta`, `noise_std`, supplied `sensitivity`, and supplied `noise_multiplier`. It performs exactly one local seeded NumPy Generator normal-vector draw with coordinate standard deviation `noise_multiplier * sensitivity`. It preserves global random state and does not mutate theta. A zero multiplier provides the matched nonprivate control. The multiplier is z, not epsilon; callers must calibrate z for one release with the existing exact GDP accountant and pass the matching solver sensitivity. Repeated releases require separate accounting. Research seeds provide reproducibility, not production secret randomness.

The sensitivity argument assumes a fixed public cohort whose clients remain nonempty, public B, lambda and T, replace-one-client adjacency, and regularization of the intercept. The implementation rejects malformed or nonfinite inputs before fitting. Input validation is not an analyzed private release policy. The proof is in exact arithmetic; float64 tests and overflow-resistant feature clipping are numerical checks, not a certified floating-point DP proof. Public hyperparameters, preprocessing, validation, diagnostics and the rest of a study are outside the output-only claim. Scalar parameterization also changes parameter count and geometry relative to a two-logit head.

Verification: `python3 -m pytest -q docs/artifacts/capstone/repro/test_client_private_erm.py` passes 58 generated-data tests. They include an independent SciPy optimizer/gradient reference, hand-derived unequal-client-weight and bound fixtures, intercept regularization, shared evaluation/fitting row clipping including extreme finite values, fixed iteration/draw counts, empirical adjacent-client distances, actual noise variance, reproducibility, input immutability, and malformed/nonfinite-input rejection. Empirical sensitivity checks are illustrations, not proofs. No framework integration, distributed transcript protection or actual-workload utility result is claimed.

A post-Torch numerical regression treats runtime warnings and floating-point divide/overflow/invalid flags as errors. On the local macOS numerical stack, BLAS matrix-vector products emitted these warnings after generated-data Torch training even with all-zero theta. For bounded generated features, actual objective/gradient values remained finite and matched independent non-BLAS contractions, SciPy sigmoid and scalar summation exactly at three tested parameter vectors. The comparator now uses explicit `einsum(..., optimize=False)` products and elementwise sums for its objective/gradient rather than suppressing warnings. This changes the numerical implementation, not the fixed update budget or release rule.

Public-constant feasibility check: with n=80, B=1 and residual ratio .01, lambda values .01, .1 and 1 select T=454, 50 and 9 respectively, all below max_steps=5000. Their total sensitivity bounds are approximately 3.57077643, .356661403 and .035499038. This checks the declared numerical budget only and provides no utility result.
